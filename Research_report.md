# Spotify Hit Prediction Research Report

## Summary

This report describes the current Spotify hit prediction pipeline and production model artifact. It replaces the earlier report sections that referenced outdated notebook plots, old XGBoost-only metrics, and inconsistent final-model conclusions.

The current production artifact is:

- Path: `music-classifier/app/hit_ensemble.joblib`
- Model class: `spotify_hit_model.ensemble.PreprocessedWeightedSoftVotingEnsemble`
- Model version: `2.0`
- Embedding model: `all-MiniLM-L6-v2`
- Candidate models evaluated in the latest artifact: XGBoost, CatBoost, Logistic Regression
- Selected production model weight: CatBoost `1.0`

The weighted ensemble machinery is still used, but the latest out-of-fold selection kept only CatBoost because adding the other candidates did not improve ROC-AUC by the configured threshold.

## Problem Definition

The project predicts whether a Spotify track should be classified as a hit (`1`) or non-hit (`0`) using historical track metadata from 1960 through 2019.

The dataset comes from the Kaggle Spotify Hit Predictor dataset and is split across six decade-specific CSV files:

- `dataset-of-60s.csv`
- `dataset-of-70s.csv`
- `dataset-of-80s.csv`
- `dataset-of-90s.csv`
- `dataset-of-00s.csv`
- `dataset-of-10s.csv`

Each row contains track identity fields, artist information, audio features, and the binary `target` label.

## Current Data Processing Pipeline

The training pipeline is implemented in `pipeline_generator.py` and `spotify_hit_model/training.py`.

Current processing steps:

1. Load all decade CSV files and add `decade_of_release`.
2. Drop duplicate tracks by `uri`.
3. Prepare public input records with strict schema validation.
4. Remove ignored model features:
   - `speechiness`
   - `instrumentalness`
5. Encode track names with `all-MiniLM-L6-v2` sentence embeddings.
6. Encode `artist` with `TargetEncoder`.
7. Encode `decade_of_release` with one-hot encoding.
8. Scale numeric model features with `StandardScaler`.
9. Train and compare candidate classifiers with stratified cross-validation.
10. Select a weighted soft-voting ensemble from out-of-fold probabilities.
11. Refit the selected model set on the full dataset and save `hit_ensemble.joblib`.

The generated feature cache is stored at `artifacts/training_features.joblib` when enabled.

## Production Serving

The project uses a single Litestar serving path in `src/spotify_prediction/api.py`. The production model artifact is generated by `pipeline_generator.py` and saved under `music-classifier/app/hit_ensemble.joblib`.

The serving API should expose:

| Method | Path | Description |
| --- | --- | --- |
| GET | `/health` | Reports model and embedding-model status |
| POST | `/predict` | Predicts one track |
| POST | `/batch_predict` | Predicts a list of tracks |

The request schema includes track title, artist, decade, and audio features. Unknown public input fields should be rejected so client mistakes are visible instead of being silently ignored.

## Current Conclusions

The earlier report stated conflicting conclusions about XGBoost, CatBoost, and Random Forest. The current production metadata supports a single conclusion:

CatBoost is the selected production classifier for the latest artifact. It achieved the best out-of-fold ROC-AUC among the evaluated candidates and remained the only model in the weighted ensemble after the ensemble selection threshold was applied.

The strongest current metrics are:

- 5-fold CV ROC-AUC: `0.9949`
- Holdout ROC-AUC: `0.9958`
- Holdout accuracy: `0.9707`
- Holdout F1: `0.9705`

These results should be interpreted as model-selection and holdout metrics for the current dataset and pipeline, not as a guarantee of generalization to future music trends or external datasets.
